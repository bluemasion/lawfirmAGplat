# 本地小模型部署 — 技术路径分析

> 前提：50 份历史投标文件，客户要求本地部署

---

## 1. 先搞清楚：本地模型要替代哪些任务？

当前系统调用 Qwen-Max 的地方有 **2 个**：

| 任务 | 调用位置 | 输入 | 输出 | 难度 |
|------|---------|------|------|------|
| **A. 结构提取** | `requirement_extraction.py` | 招标原文 (~5000字) | JSON (章节列表) | ⭐⭐ 中等 |
| **B. 叙述方案生成** | `content_generation.py` | 章节标题 + 要求 + Self-RAG 参考 | 投标方案文本 | ⭐⭐⭐⭐ 很难 |

> **关键判断**：任务 A（结构提取）非常适合小模型；任务 B（方案生成）对小模型挑战很大。

---

## 2. 三条技术路径对比

### 路径 1：微调小模型做结构提取（替代任务 A）

```
招标文件原文 → 微调后的 Qwen-7B → tender_requirements.json
```

| 项目 | 详情 |
|------|------|
| **基座模型** | Qwen2.5-7B-Instruct（14GB）或 Qwen2.5-3B-Instruct（6GB） |
| **训练方法** | LoRA / QLoRA（只训练 1-5% 参数，显存占用低） |
| **训练数据** | 50 对 (招标原文 → 结构化 JSON)，可用 GPT/Qwen-Max 辅助标注 |
| **显存需求** | 7B + QLoRA ≈ 16GB（1 张 RTX 4090 够用）|
| **训练时间** | 2-4 小时 |
| **推理速度** | 7B：~30 token/s（4090）；3B：~60 token/s |
| **效果预估** | 50 对高质量数据 SFT，结构提取准确率应达 85-95% |

> [!TIP]
> **这是投入产出比最高的方案。** 结构提取是"理解→JSON"任务，模式固定，小模型学得快。

---

### 路径 2：微调小模型做方案生成（替代任务 B）

```
章节标题 + 招标要求 + RAG参考 → 微调后的 Qwen-7B → 投标方案段落
```

| 项目 | 详情 |
|------|------|
| **基座模型** | Qwen2.5-7B-Instruct 或 Qwen2.5-14B-Instruct |
| **训练方法** | LoRA SFT |
| **训练数据** | 需要 (章节标题+要求 → 高质量投标内容) 对，约 500-1000 对 |
| **数据来源** | 50 份标书 × 10-15 个叙述章节 ≈ 500-750 对 |
| **显存需求** | 14B + QLoRA ≈ 24GB（A100 40GB 推荐）|
| **效果风险** | ⚠️ **高风险**：叙述生成需要创造力 + 专业知识，7B 模型可能写得太模板化 |

> [!WARNING]
> 方案生成是开放式文本生成，7B 模型的表达能力有限。效果可能不如 Qwen-Max API + Self-RAG。建议只在客户严格要求数据不出本地时才走这条路。

---

### 路径 3：不训练，用开源模型 + RAG（折中方案）

```
不微调，直接部署 Qwen2.5-7B-Instruct + 历史标书向量库
```

| 项目 | 详情 |
|------|------|
| **模型** | Qwen2.5-7B-Instruct（原始权重，不微调） |
| **增强手段** | 50 份历史标书 → chunk → embed → 向量库（和现在的 Self-RAG 同一架构） |
| **优势** | 零训练成本，部署即可用 |
| **劣势** | JSON 输出格式不稳定，需要更多 prompt engineering |
| **显存** | 7B FP16 ≈ 14GB，INT4 量化 ≈ 4-5GB |

> [!NOTE]
> 这条路最快（1-2天部署完），但质量取决于 prompt 工程。适合作为快速验证方案。

---

## 3. 推荐策略：两步走

### Phase A（1-2 周）：先部署 + RAG

```
Qwen2.5-7B-Instruct (INT4量化)  ← 4-5GB显存，消费级显卡就行
        + 
历史标书向量库 (50份 → BGE embed → 检索)
        +
当前投标管线（Self-RAG + 代码模板）
```

**目的**：验证本地模型的基础能力，收集实际效果数据

### Phase B（2-4 周）：微调结构提取

```
50 对训练数据（招标原文 → JSON）
        ↓
QLoRA 微调 Qwen2.5-7B
        ↓
替换 API 调用，完全本地化
```

**目的**：消除 API 依赖，提升结构提取稳定性

## 5. 训练数据准备方案 (50 份标书)

### 任务 A：结构提取数据

```python
# 数据格式 (每份标书生成 1 条训练样本)
{
  "instruction": "提取以下招标文件的投标结构要求，输出 JSON 格式",
  "input": "招标文件原文 (5000-15000字)",
  "output": "{\"bid_title\":\"...\", \"volumes\":[{\"name\":\"...\", \"sections\":[...]}]}"
}
```

**生成方式**：用 Qwen-Max 先跑一遍 50 份，人工校正 JSON → 得到训练数据

### 任务 B：方案生成数据

```python
# 数据格式 (每个叙述章节生成 1 条训练样本)
{
  "instruction": "根据招标要求，撰写投标方案章节",
  "input": "章节标题: 项目实施方案\n要求: ...\n参考: ...",
  "output": "历史标书中该章节的实际内容"
}
```

**生成方式**：直接从 50 份历史标书中拆出叙述章节 → 约 500-750 条

## 6. 需要确认的问题

1. **客户硬件**：有 GPU 服务器吗？什么配置？
2. **数据隐私**：客户是完全不允许数据出本地（API 也不行），还是只要最终部署在本地？
3. **50 份标书格式**：都是 .docx 吗？有对应的招标文件吗（成对的）？
4. **效果预期**：客户能接受"80% 场景自动生成 + 20% 人工修改"吗？
